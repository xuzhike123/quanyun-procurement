# 调用前置信息采集（Intake Gate）

> **本卡是硬门禁，不是参考建议。** 调用本 Skill 后，第一步先核对输入信息；「一、必写」6 项与本次命中的「二、按场景」项未填齐之前，**不得输出任何档位、审批主体、采购方式、流程环节或条文依据**，唯一允许的输出是第五节规定的「信息采集表」。

## 一、必写（缺任一项 → 判停索要数据，不猜档位）

| # | 事项 | 要写到什么程度 | 依据 |
|---|---|---|---|
| 1 | 采购主体 | 集团本部 / 分公司 / 全资子公司 / 有实际控制权的相对控股企业 / 权属企业（写明具体单位） | `scope-attribution` 完成标准 1；`approval-route` 完成标准 3 |
| 2 | 采购标的 | 一句话说清「买什么」，并落到货物或服务的具体类目 | `scope-attribution` 完成标准 2 |
| 3 | 估算价 | 单项或批量估算价的**具体数字**；含币种与计价口径（单项 / 批量 / 年预算 / 合同总额） | `SKILL.md` 边界与判停；`approval-route` 完成标准 1 |
| 4 | 预算状态 | 预算内 / 预算外 / 超预算；超预算须给增幅 % 与增额 | `approval-route` 完成标准 1、5 |
| 5 | 是否属工程 | 是否工程建设项目或与其有关的货物服务；混合项目须给工程建设部分**占比数值与算法** | `scope-attribution` 完成标准 3、4（≥50% 转工程制度） |
| 6 | 资金来源与射程例外 | 是否财政性资金；是否工会经费等非行政支出、商业流通 / 购销差价、品牌代理、上市公司 | `scope-attribution` 完成标准 3 |

> 判停原文依据：`SKILL.md`「边界与判停」——采购金额、采购类型或是否预算内无法确定时，先索要数据，不猜测档位。

## 二、按场景必须补写（命中即硬性，不写会走错分支）

必写 6 项齐备后，依已填内容判断命中哪些场景；命中项同样未填齐前**继续停在采集表**。

| 命中条件 | 需补写 |
|---|---|
| 主体为权属企业 | 是否已履行内部三重一大决策、是否已上请示、本企业备案制度金额门槛（可能更严） |
| 需选定采购方式 / 拟用邀请招标、单一来源 | 拟用方式；命中情形编号；流标须写明「是否修改招标文件」 |
| 拟采用内部采购 | 承接方股权关系（全资 / 绝对控股 / 有实际控制权相对控股）、是否转包、定价基准来源（成本价 / 行业指导价 / 进价 / 概算） |
| 标的为租赁、服务类或金额按年计 | 年使用费、合同期累计、**租赁年限**（>5 年不含直接触发董事会）、是否跨年度及计价口径 |
| 应急采购 / 零星小额 / 20 万元以下 | 是否 <20 万、是否常规重复性可批量归集、**紧急情形解除的具体日期**（据此推算 5 个工作日） |
| 涉及台账、备案、报送时限 | 招标完成日或情形解除日、合同金额是否 >1 万、是否限额以上 |
| 涉及招标文件挂网 / 200 万元以上 | 是否依法必须招标、估算价是否 ≥200 万、招标文件是否已挂网 |
| 涉及合规判断、责任追究 | 行为的一句话事实（时间、主体、对象、具体动作）、需求 / 询价 / 定价 / 采购 / 验收 / 结算六环节实际经办人、反对意见证据来源 |
| 需要核对前置程序 | 是否已立项、党委前置研究、董事会 / 总经理办公会；会议排期与经办人 |

## 三、建议写（影响精度，不阻塞）

- **用途 / 立项原因**：决定附件1 归口部室（例：「公务用车租赁」归综合部，一般性「租赁」归相关业务部室）。
- **集团最新解释口径**、**附件2 版本日期**：附件2 标注「动态更新」，与正文可能漂移。
- **权属企业备案制度文本**：其标准可能更严，优先适用。

缺失处理：不判停，但必须在结论末尾以「未给出 / 按 X 假设 / 我不知道」逐项标注，不得静默假设。

## 四、写了也不给结论（不适用范围）

具体人员的责任认定与纪律处分定性（只给制度依据）、供应商报价是否合理（需市场行情数据）、法律意见书与审计结论、工程建设项目招投标细节、代替企业作出实际决策或代签审批文件。这些即使写齐也不输出定性结论。

## 五、采集表（未填齐时唯一允许的输出）

执行顺序：

0. **先判豁免**：纯术语解释、整书概览、书名 / 作者 / 章节类问题不产生判定结论，可跳过本门禁直接回答；其余一律执行。
1. 逐项比对「一、必写」6 项，标出已填 / 缺失。
2. 依已填的标的、金额、主体、预算状态判定命中哪些场景，列出「二、按场景」中本次需补写的项。
3. 输出采集表，**一次问齐**，不逐项来回追问；用户回复后只追问仍缺失的项，不重复询问已填项。
4. 必写项 + 命中的场景项全部齐备后，才按路由表加载能力卡并给出结论与条文依据。
5. 用户明确要求「先给大致判断 / 按最可能情形先出」时，可以出结论，但须整篇标注「基于未填齐信息的初判，待补齐后复核」，且不得作为可直接报批的最终流程。
6. 建议写项缺失按第三节处理。

输出格式（固定，禁止夹带档位判断、主体判断或条文号）：

```
【调用前置信息采集】以下 N 项需要你补充，补齐后我再给出完整流程与条文依据。

| 项目 | 状态 | 需要你补什么 |
|---|---|---|
| 采购主体 | 已填 / 缺失 | … |
| … | … | … |
| （命中场景项） | 缺失 | … |

可直接复制填写：
@skill:qycg-skill 采购主体是【…】，采购标的是【货物/服务：具体名称】，
单项或批量估算价【XX 万元，计价口径】，预算状态【预算内/预算外/超预算，增幅 X%、增额 X 万】，
【不属工程建设项目/工程建设占比 X%】，资金来源【…】，用途【…】。
```
